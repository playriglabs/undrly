# V1.1: universe expansion (design)

Status: **approved design** (decision §12: option A, local-only universe data). Branch `v1.1-universe`. V1 is
frozen at tag `v1.0.0`.

Goal: move from five representative instruments to a useful cross-market
universe **without changing** the quote architecture, canonical ids, the
observation/aggregation/provenance models, or the API's existing semantics.
Everything below is additive.

Counts in this document were measured live on 2026-09-25 against the
sources in §9. They will drift with each snapshot; the import report records
the actual numbers for each build.

## 1. Universe model (migration 0011)

"An instrument exists" and "an instrument belongs to universe U as of T" are
separate facts.

```sql
universe_snapshots (
  id, universe_key text CHECK (IN ('crypto-top100','sp500','nasdaq100','hyperliquid-perps')),
  as_of timestamptz NOT NULL,            -- the source's own as-of date
  source_id, received_at, source_record_id,  -- composite provenance FK, as for every fact
  UNIQUE (universe_key, source_record_id)
)
universe_members (
  snapshot_id → universe_snapshots, node_id/node_category → nodes,
  rank integer NULL,                     -- source rank (e.g. market-cap rank); metadata only
  source_symbol text NULL,               -- as the universe source spells it
  PRIMARY KEY (snapshot_id, node_id)
)
```

- The current membership of a universe is its latest snapshot. Old snapshots
  stay as history.
- Membership never affects canonical ids. Rank is data, not identity.
- No index engine: no weights, no rebalancing, no portfolio math.

Also in 0011 (all additive, all agreed in the plan):

| Change | Why |
| --- | --- |
| `quote_feeds.stale_after_seconds integer NOT NULL DEFAULT 300 CHECK (> 0)` | Freshness per feed (§4). The default keeps V1 feeds exactly as they are. |
| `instruments.contract_multiplier financial_decimal NULL CHECK (> 0)` | `kPEPE` is 1,000 PEPE; its mark price is per contract. |
| `instruments.unit_of_measure text NULL CHECK (IN ('troy_ounce','barrel','mmbtu','metric_ton','kilogram'))` | A commodity price is meaningless without its unit. |
| price type `average` (vocabulary) | World Bank publishes **monthly averages**: neither spot nor futures. |

No new identifier namespace and no new primary identifier (§2).

## 2. Identity and mapping rules

| Asset class | Canonical identity | How source symbols map |
| --- | --- | --- |
| Crypto asset | generated UUIDv7, pinned in the id map under its **CoinGecko id** (`bitcoin`) | Kraken and Coinbase markets map to CoinGecko ids through **CoinGecko's own exchange tickers** (each ticker names its `coin_id`). Venue pair symbols (`XXBTZUSD`, `BTC-USD`) are feed symbols only. |
| Perpetual | generated UUIDv7, pinned under `hyperliquid:<market name>` | Its underlying comes from **CoinGecko's Hyperliquid derivatives tickers** (`coin_id`), matched to Hyperliquid's main-market names (case-insensitive, main markets only). No crosswalk → no `DERIVES_FROM` edge. |
| Equity | generated UUIDv7 (the only identity), pinned in the **local** id map under a build-local key `spy:<CUSIP>`. The CUSIP is never stored or exposed as an identifier, and **no ISIN is constructed from it**. | Listing symbol on its primary venue (MIC from SEC's `company_tickers_exchange.json`: NYSE → `XNYS`, Nasdaq → `XNAS`, CBOE → `BATS`). Class-share punctuation normalized by one explicit rule (`BRK.B` ↔ `BRK-B`). Issuer entity with its **CIK** from the same SEC table (one entity per CIK; share classes share it). |
| Commodity | curated (14 entries, hand-listed: a benchmark list, not a data dump) | gold-api / EIA / World Bank series codes are feed symbols. |

- **Never construct security identifiers from assumptions about domicile or
  symbol structure. Missing identity enrichment is preferable to guessed
  identity.** `US` + CUSIP is wrong for non-US issuers: 29 SPY holdings have
  CINS CUSIPs, and some digit CUSIPs are foreign too (SLB →
  `AN8068571086`).
- An imported equity is: canonical instrument + issuer entity when known +
  venue/listing + venue-scoped symbol + provenance/universe membership.
  ISIN/FIGI are optional enrichment. When an authoritative source is added
  later, they are attached to the existing instrument, never used to mint a
  new one. Pinned V1 identifiers (NVDA's ISIN and FIGIs) are preserved.
- **CIK identifies the issuer entity only**, never the instrument. It comes
  from SEC's ticker table, SEC's own crosswalk.
- **Never** from a bare symbol. A crypto asset without a crosswalked venue
  market gets no quote feed; a perp without a crosswalked underlying gets no
  edge; a Nasdaq-100 member without a trustworthy identifier is skipped
  (decision 4) and listed in the import report.
- **Symbol matching would have been wrong.** For the top 100, naive symbol
  matching says 55/24/21 (both/Kraken-only/none); the crosswalk says
  **59/18/23**.
- **V1 ids are reused**: the id map is initialised from the curated V1
  universe (`bitcoin` → V1 Bitcoin, `usd-coin` → V1 USDC,
  `hyperliquid:BTC` → V1 BTC-PERP, `spy:67066G104` → V1 NVDA (a hand-pinned
  entry), `sec:1045810` → V1 NVIDIA,
  `XAU` → V1 Gold), so nothing is duplicated and V1's demo keeps working.
- **Issuer entities carry a CIK only** (no LEI in V1.1). NVIDIA keeps its V1
  entity. Merging LEI and CIK nodes of one issuer is Phase 5.

## 3. Deterministic snapshot and rebuild

```text
undrly-collect universe fetch   → data/universe/raw/<source>/<file> + manifest.json (url, sha256, bytes, fetched_at)
undrly-collect universe build   → data/universe/snapshot.json + data/universe/report.md   (pure)
undrly-collect seed             → V1 curated universe, then the snapshot, through raw-first ingestion
```

- `fetch` is the only networked step. It paces CoinGecko at one request per
  7 s and waits on HTTP 429.
- `build` is pure: the same raw files and the same id map produce
  **byte-identical** outputs. Everything is sorted, there are no wall-clock
  timestamps (only sources' own as-of dates), and there is no randomness
  except for ids.
- The **id map** (`data/universe/ids.json`, source key → canonical id) is the
  only stateful input. Existing keys keep their ids forever; new keys get a
  new UUIDv7, recorded in the map. Keys that disappear keep their entry, so
  a re-listed asset gets its old id back.
- The **import report** lists, per universe: the as-of date, the source hash,
  counts, and **every exclusion with its reason**.
- `seed` stores each raw universe file as a source record, keyed by URL,
  with its fetch time. The built `snapshot.json` is itself stored as a
  record of source `undrly-universe`, and names every upstream file by
  source, record key and SHA-256.
  - Instruments, entities, identifiers, aliases, listings, edges, feeds and
    aggregation declarations name the snapshot record.
  - Each universe membership names the upstream record that asserted it
    (e.g. the SPY file).

## 4. Feed-aware freshness

Each feed declares `stale_after_seconds`:

| Feed | Cadence | `stale_after_seconds` |
| --- | --- | --- |
| Kraken, Coinbase, Hyperliquid | market data | 300 (V1 default; BTC/USD's `mean-venue-mid-v1` keeps its own 30 s) |
| Alpaca IEX | market data during US sessions | 300 |
| gold-api metals | frequent reference | 300 |
| EIA daily spot series | daily, published with a lag of up to a week | 1,209,600 (14 days) |
| World Bank monthly averages | monthly, published early in the following month | 5,356,800 (62 days) |

- The API computes freshness from the **selected observation's feed** (a join
  on source, subject, unit, venue and price type). This replaces the global
  `UNDRLY_STALE_AFTER_SECONDS` for pairs whose feeds declare a value; V1
  feeds declare 300, so V1 output is unchanged.
- `mean-venue-mid-v1` keeps its fixed 30 s window, both for eligibility and
  at read time (unchanged).
- This is a per-feed number, not a scheduler. The collector keeps its fixed
  per-source polling intervals (§5).

## 5. Quote batching and rate limits

| Source | Requests | Interval | Notes |
| --- | --- | --- | --- |
| Kraken | comma-separated pair names, packed so each request URL (the record key, ≤ 256 characters) fits: 3 requests for 80 pairs, 1 s apart | 10 s | Measured: ~3.2 s per poll |
| Coinbase | 1 level-1 book request per product (59), one at a time, ≥ 150 ms apart | 10 s (a new sweep starts when the last one ends) | Kept under Coinbase's public ~10 req/s. Each response is its own raw record. **Measured sweep: 23–29 s**, just inside BTC/USD's 30 s window. |
| Hyperliquid | 1 `metaAndAssetCtxs` request covers all perps | 15 s | Unchanged |
| Alpaca IEX | snapshots for as many symbols as fit a ≤ 256-character URL (~40 per request, ~13 requests for 503) | 30 s | Free plan allows 200 req/min |
| gold-api | 1 request per metal (4) | 60 s | |
| EIA | 2 requests: petroleum spot (WTI, Brent) and natural gas (Henry Hub) are separate API routes | 6 h | Needs `EIA_API_KEY`. It travels only in the URL; the record key omits it, and a response that echoes it is discarded, never stored. |
| World Bank | 1 monthly workbook (each edition has its own URL, found on the commodity-markets page) | 24 h | ~590 KB. Cells are doubles stored with 17 significant digits; the normalizer rounds them in decimal to 15 (`1.1000000000000001` → `1.1`). Observation time = end of the averaging month. |
| CoinGecko | none at collection time | — | Used only by `universe fetch` |

Two small, non-architectural changes to ingestion:

1. **Records cover a subset of a source's feeds.** A Coinbase record is one
   product, and an Alpaca record is one batch. `ingest_quotes` gains an
   optional *requested symbols* argument, so feeds outside a record are
   neither matched nor reported missing. It's `None` for V1 sources, so
   their behaviour is unchanged.
2. **The Coinbase normalizer** keeps its rule of one product per record.

**Scheduling** (measured with the full universe):

- **Continuous mode:** a source's poll is a queue of requests. Between two
  requests the collector serves whichever source is due first, so the
  Coinbase sweep never holds Kraken back from its 10 s cadence.
- **`run --once`** (used by `demo.sh`): sources run slowest-moving first,
  and the venue pair (Coinbase, then Kraken) last. The Coinbase sweep runs
  in reverse declaration order, so the pass ends with the V1 pairs fresh.
  Without this, a 33 s pass left BTC/USD's aggregate outside its window
  (19/22); with it, 22/22.
- A Coinbase product whose book hasn't changed for more than 30 s (e.g.
  USDS-USD) is correctly ineligible for `mean-venue-mid-v1`; the pair then
  aggregates the other venue alone.

Everything stays sequential: no concurrency, no retries beyond the next
tick.

**Known scaling limitation (Coinbase).** The sequential Coinbase sweep
takes 23–29 s for 59 products, so a full `run --once` pass takes about
46 s. The sweep nearly fills BTC/USD's 30 s aggregation window: in a pass,
the products swept first (the end of the reversed order, e.g. XRP-USD,
USDT-USD) are more than 30 s old by the time Kraken finishes, so their
pairs aggregate Kraken alone (8 of 59 in the measured pass). Adding
Coinbase products makes this worse linearly. Future collector work:
bounded concurrency or batching for Coinbase. Not addressed in V1.1.

**Storage growth** (retention deferred): roughly **100–150 MB per hour** of
raw records and observations at these intervals. Alpaca batches (~40 MB/h),
Hyperliquid (~17 MB/h) and observation rows (~140k/h) dominate. V1.1 is for
short local/private sessions; long-running collection needs a retention
policy first.

## 6. Search and resolve at scale

Existing rules are unchanged: exact matches only, never a guess, and
`ambiguous` lists the candidates. Two deterministic refinements, both the
same rule V1 already uses for `NVIDIA` in `/v1/quote`:

- **Pairs** (`ETH/USD`): if a side's symbol matches several nodes (for
  example a crypto symbol that is also a stock ticker), only combinations
  that have a quote feed are kept. Exactly one → resolved.
- **Bare symbols** stay `ambiguous` in `/v1/resolve` when several nodes match.
  `/v1/quote` keeps its V1 behaviour: exactly one priced candidate → that
  quote; otherwise 409 with candidates.
- **Aliases generated:**
  - crypto: CoinGecko symbol (upper-cased) and name;
  - equities: listing symbol and security name;
  - perps: `<NAME>-PERP` and "<Name> perpetual";
  - commodities: name and source code.
- **Collisions** (symbols shared across asset classes) are counted in the
  import report, and the README documents the unambiguous forms: pair
  (`ETH/USD`), venue symbol (`NASDAQ:AAPL`, `COINBASE:ETH-USD`,
  `HYPERLIQUID:ETH`), identifier (`isin:…`) or id.
- **Search** is unchanged: ranking by match type (exact alias, exact name,
  prefix, substring), limit 20.

## 7. API contract: universe membership (additive)

```jsonc
// GET /v1/universes
{ "schemaVersion": 1,
  "universes": [
    { "key": "crypto-top100", "name": "Crypto top 100 by market cap",
      "source": { "id": "coingecko" }, "asOf": "2026-09-25T08:32:20Z", "memberCount": 100 } ] }

// GET /v1/universes/{key}
{ "schemaVersion": 1,
  "key": "sp500", "name": "S&P 500 (via SPY holdings)",
  "description": "SSGA SPY ETF holdings: a practical proxy, not the official S&P constituent file.",
  "source": { "id": "ssga" }, "asOf": "2026-09-23T00:00:00Z",
  "sourceRecord": { "id": "123" },
  "memberCount": 503,
  "members": [ { "node": NodeRefV1, "rank": null, "sourceSymbol": "NVDA" } ] }
```

- Keys: `crypto-top100`, `sp500`, `nasdaq100`, `hyperliquid-perps`. An unknown
  key returns 404 `not_found`.
- Members are listed in the source's order (rank if it has one, else symbol).
  There's no pagination: the largest universe has 503 members.
- Membership is snapshot metadata. `/v1/quote` and `/v1/resolve` don't change
  because of it.

## 10. Tests

- **Pure (offline):**
  - every parser: CoinGecko markets, exchange tickers, derivatives tickers, Hyperliquid meta, SPY XLSX, the Nasdaq list, SEC tickers, EIA, World Bank;
  - CUSIP check-digit validation (a build-key sanity check; no ISIN is constructed);
  - `k`-prefix → multiplier 1000;
  - no mapping without a crosswalk;
  - exclusions reported with reasons;
  - **`build` determinism** (same inputs → identical bytes; the id map is preserved; only new keys get new ids).
- **Fixtures:** small checked-in captures for permissively licensed sources,
  and **synthetic** fixtures in the real formats for restricted ones
  (clearly labelled), pending §12.
- **Database:**
  - seeding a synthetic universe creates instruments, listings, aliases, feeds, aggregation declarations and memberships with provenance;
  - batched Alpaca and per-product Coinbase ingestion with requested symbols;
  - per-feed freshness (EIA 14 d, World Bank 62 d);
  - `mean-venue-mid-v1` for a second pair.
- **API (database-backed):**
  - `/v1/universes` and `/v1/universes/{key}`;
  - pair disambiguation;
  - freshness by feed;
  - no upstream calls (as in V1).
- **V1 regression:** `demo.sh` 22/22 and the BTC/USD aggregation tests,
  unchanged.
- **Live, opt-in (`--ignored`):** `universe fetch` smoke test, EIA fetch.

## 12. Decision: third-party universe data is local-only

Decided: **option A**. The SSGA holdings file forbids reproduction without
consent, and CUSIPs are licensed. So:

- `data/universe/` (raw upstream files, the generated snapshot, the id map
  and the import report) is **git-ignored**. Each machine runs
  `universe fetch` and `universe build` locally.
- Committed: the tooling, the V1 curated universe, the curated commodity
  list (`data/reference/commodities.json`, Undrly-authored), **synthetic**
  test fixtures in the real formats (clearly labelled), and captures of
  permissively licensed sources (World Bank, EIA).
- Canonical ids are stable per machine, through the local id map, and not
  across machines. V1's pinned ids are the same everywhere.
- The import report (`data/universe/report.md`) is the review artefact.
- Credentials: `EIA_API_KEY` and `UNDRLY_SEC_USER_AGENT` come only from the
  environment (`.env`). They are never written to files, logs or record keys.

## 13. Decision: Nasdaq-100 live import deferred

Universe support is modeled, but live membership import is deferred pending
an approved machine-readable source.

- nasdaq.com's list endpoint refuses non-browser clients. We don't
  impersonate a browser, work around source restrictions, or hand-download a
  file to fill the universe.
- `universe fetch` no longer requests the list; `universe build` records
  `nasdaq100: not built` in the import report, and `/v1/universes/nasdaq100`
  returns 404 `not_found` (no snapshot).
- The key, schema, parser and matching rule (members must be imported S&P
  500 securities listed on Nasdaq under the same symbol) stay in place and
  tested, for when an approved source exists.
