# V1.3: market data surface

Status: implemented locally on branch `v1.1-universe` (not committed).
Measured on **2026-09-26 (a Saturday)**.

V1.3 adds no instruments, providers or universes. It makes the 951
existing instruments more useful through four new read-only endpoints:

- `/v1/candles` (venue OHLCV);
- `/v1/history` (reference series);
- `/v1/market` (status and statistics);
- `/v1/derivatives` (perpetual context).

Collection keeps the existing shape: collector → normalize → store → API.
The API never calls a provider.

## 2. Storage (migration 0015)

| Table | Row | Key (idempotency) |
| --- | --- | --- |
| `market_bars` | one venue OHLC bar: market (subject, unit), source, venue, interval (`1h`, `1d`), open/close time, O/H/L/C, volume (subject units, nullable), trade count, record | `UNIQUE (subject, unit, source, venue, interval, open_time)`. A newer record with different values replaces a bar that was still in progress; an older or identical record changes nothing. |
| `perp_contexts` | a perpetual's context from one Hyperliquid poll: mark, oracle, mid, funding (fraction per `funding_interval_hours`), open interest, 24h base/notional volume, price 24h ago | `UNIQUE (source_record_id, subject_id)` |
| `trading_sessions` | a venue's trading date with pre-open / open / close / post-close instants | `PRIMARY KEY (venue_id, session_date)` |
| `trading_calendar_ranges` | the dates a loaded calendar covers (a covered date without a session is closed) | `UNIQUE (source_record_id, venue_id)` |

- **Reference-series history** is ordinary `market_observations`: each is
  one source's value at one source time.
  - The record key now includes `observed_at`, because a 90-day payload
    yields one observation per date.
  - A partial index `(subject, unit, source, observed_at DESC)` serves
    `/v1/history`.
- **Columns:** every financial field is a `financial_decimal` column, with
  no JSON. Every row names its raw source record.
- **Nothing derived is stored.** 4h candles, market statistics and status
  are computed at read time.
- **Index use:** `/v1/candles/BTC/USD?interval=1h&limit=100` is an index
  scan backward on `market_bars_one_per_period` (3.7 ms in `EXPLAIN
  ANALYZE`). It never scans the table.

## 3. Collection

```text
undrly-collect history [bars|reference|calendar|all] [--days-1h N] [--days-1d N]
```

Every step is sequential, stores the raw record first, and is idempotent.
Re-running it replaces only bars that were in progress; overlapping
reference payloads leave 7,092 of 7,092 prior values unchanged.

- **Bars:**
  - Kraken: one pair and interval per request, 1 s apart.
  - Hyperliquid: one coin and interval, 1.5 s apart.
  - Alpaca: symbol batches that fit a 256-character record key, with every
    page followed.
  - Defaults: 30 days of `1h` and 365 days of `1d` (Kraken caps at 720
    bars).
- **Perpetual contexts:** the existing `run` loop's Hyperliquid poll (every
  15 s) now also stores each perpetual's context, from the same raw record
  as the mark price. No extra request.
- **Not in the continuous loop:** bars and the calendar are refreshed by
  re-running `history`. The statistics' `to` time shows how current the
  bars are.

## 4. API (contract v1, additive; error code `no_data` added)

| Route | Returns | Semantics |
| --- | --- | --- |
| `GET /v1/candles/{q}?interval=1h\|4h\|1d&limit=1..1000&start=&end=` | `CandlesV1` | One venue's trade bars, oldest first. The venue is not named in the response (no venue or provider identity). `complete: false` marks a bar that was in progress when collected. `4h` is `derived: true`: four consecutive UTC-aligned hours (open of the first, max high, min low, close of the last, summed volume); a period missing any hour is omitted, never filled. The venue with the newest bar is used; each market has exactly one bar source by construction (Kraken, Hyperliquid or IEX). |
| `GET /v1/history/{q}?limit=&start=&end=` | `HistoryV1` | For reference or average series only: the values published by the feed behind the current canonical quote, oldest first, as `{asOf, price}`. **Never OHLC.** |
| `GET /v1/market/{q}` | `MarketV1` | The canonical quote's price, type, basis, `asOf` and freshness, plus `marketStatus` and `statistics`. |
| `GET /v1/calendar/{q}?from=&to=` | `CalendarV1` | For session markets (equities): the trading sessions of the venue their quotes come from, by New York date, with `open`/`close` (regular) and `preOpen`/`postClose` (extended), `earlyClose` (regular session under 6 h 30 min), `closedWeekdays` (holidays: weekdays inside the loaded calendar without a session) and the calendar's `coverage`. Dates default to today (New York) + 14 days, at most 366 days; invalid or reversed dates are `400`. Continuous markets and reference rates are `404 no_data`. `events` lists corporate actions (Alpaca: cash/stock dividends, forward/reverse splits, spin-offs, cash/stock mergers, name changes) whose ex/effective/process date falls in the window, with the instrument's `role`, per-share `cashAmount` (Alpaca states no currency), `stockRate`, `ratio` (old : new) and the other security's symbol as spelled by the source. Loaded by `history corporate-actions` (a year back, six months ahead; about 21 s for the S&P 500; a revised action replaces the stored one; reorganizations, unit splits and worthless removals are skipped and counted). |
| `GET /v1/derivatives/{q}` | `DerivativesV1` | A perpetual's latest venue context. Hyperliquid states no time, so `asOf` is the receipt time; freshness uses the mark feed's 300 s window. |

**Invalid requests.**
- A bad `interval`, a `limit` outside 1..1000, a non-RFC-3339 `start` or
  `end`, or `start >= end` → `400 bad_request`.
- A market with no data for that endpoint → `404 no_data` (for example a
  reference pair's candles, a traded pair's history, or a non-perpetual's
  derivatives).
- An unknown market → `404 not_found`.
- Ambiguity behaves as in `/v1/quote`.

**`marketStatus`**

| Value | When |
| --- | --- |
| `continuous` | crypto spot, perpetuals, and Kraken/Bitstamp FX (those venues trade their books around the clock) |
| `open` / `pre_market` / `after_hours` / `closed` | equities, from IEX's loaded calendar (Alpaca `/v2/calendar`: holidays and early closes) |
| `unknown` | a date outside the loaded calendar |
| `null` | reference or average series, which are publications, not traded markets |

NVDA's stale quote at a weekend now reads `marketStatus: "closed"`.

**`statistics`**

| Window | Markets | Definition |
| --- | --- | --- |
| `rolling_24h` | continuous | The 24 consecutive `1h` bars ending with the latest: `open` of the first, max `high`, min `low`, `close` of the latest, summed `volume`, `change = close - open`. |
| `session` | equities | The venue's latest `1d` bar (its New York trading day), with `previousClose` from the bar before it and `change = close - previousClose`. |

- `changePercent` is half to even at 4 places.
- A gap in the bars makes `statistics` `null`.
- Statistics come from one venue's bars (the same bars as `/v1/candles`)
  but do not name it: no venue or provider identity in `/v1/market`.

**Derivatives units.**

| Field | Unit |
| --- | --- |
| prices | ~~the settlement unit (USDC)~~ the contract's price denomination: USDT for most perpetuals, USDC for PURR and HYPE (corrected in V1.4.1: most Hyperliquid perpetuals are USDT-denominated and USDC-margined; see [`v1.4-cross-ecosystem-identity.md` §15](v1.4-cross-ecosystem-identity.md#15-hyperliquid-contract-semantics)) |
| `indexPrice` | Hyperliquid's oracle price (a weighted median of CEX spot prices) |
| `fundingRate` | a fraction per `fundingIntervalHours` (1), not annualized |
| `openInterest`, `volume24h` | contracts (see the subject's `contractMultiplier`) |
| `volume24hNotional` | ~~USDC~~ the price denomination (contracts × price) (corrected in V1.4.1: most Hyperliquid perpetuals are USDT-denominated and USDC-margined; see [`v1.4-cross-ecosystem-identity.md` §15](v1.4-cross-ecosystem-identity.md#15-hyperliquid-contract-semantics)) |
| `price24hAgo` | as the venue states it |

## 4b. Event calendars

| Data | Source | Where | Semantics |
| --- | --- | --- | --- |
| Corporate actions | Alpaca `/v1/corporate-actions` (existing source) | `/v1/calendar/{q}` → `events` | Cash/stock dividends, forward/reverse splits, spin-offs, cash/stock mergers and name changes for equities, attached by the instrument's Alpaca feed symbol and role. The source's terms are kept exact. Reorganizations, unit splits and worthless removals are skipped and counted. Revisions replace. |
| Earnings | Finnhub `/calendar/earnings` (new, `FINNHUB_API_KEY`) | `/v1/calendar/{q}` → `earnings` | Report date, time (`before_open`, `after_close`, `during_hours`, or `null`), fiscal year/quarter, and Finnhub's EPS/revenue consensus and actuals (no currency stated). Matched to equities by their IEX feed ticker; other tickers are ignored. |
| Economic releases | FRED `release/dates` (new, `FRED_API_KEY`) | `/v1/economic-calendar` | Scheduled dates (no time of day, forecasts or figures) of 14 curated releases in `data/reference/economic-releases.json`: CPI, PPI, PCE, jobs report, weekly claims, JOLTS, ECI, productivity, GDP, retail sales, industrial production, housing starts, UMich sentiment, trade balance. Each fetch is a snapshot of its window; a date is read from the newest snapshot covering it, so a moved or cancelled date disappears. The response carries FRED's required notice. |

`history corporate-actions` loads a year back to six months ahead (~21 s
for the S&P 500). `history economic` loads a month back to six months ahead
(14 requests, ~14 s). `history earnings` loads a month back to three months
ahead in two-week windows (9 requests, ~23 s). Measured on `undrly_v11`:

| Data | Loaded |
| --- | --- |
| Corporate actions | 1,874 for 403 S&P 500 names |
| Earnings | 352 reports for 316 names |
| Economic releases | 72 scheduled dates across 14 releases |

**Gaps.**
- The **FOMC meeting schedule**: FRED's "FOMC Press Release" (101) is a
  daily data update, not the meeting calendar, and the Fed publishes the
  schedule only as HTML.
- **Economic consensus forecasts and actual figures.**
- **Earnings for tickers outside Undrly's equities.**

**Terms.**
- Finnhub's free plan is personal-use only and forbids redistribution.
  Its test fixture is **synthetic** (real format), and the data stays
  local.
- FRED allows application use with its notice. Third-party series need
  their owners' permission; only FRED's own schedule metadata is used.

## 5. Not implemented, and why

| Item | Reason |
| --- | --- |
| Spot↔perp basis (Phase G) | Every perpetual is priced in **USDC** (V1.4.1: in **USDT**, except PURR and HYPE in USDC); every spot market in **USD**. The units are not compatible, and converting USDC to USD would be a derived rate V1.3 does not have. `basis` and `basisBps` are not exposed. |
| Analytics (Phase H) | Not built. `/v1/market` already states the one precisely defined window change. Realized volatility would need an explicitly approved return definition and minimum-coverage rule. |
| `nextFundingAt` | Hyperliquid's `predictedFundings` reported the current hour's start as the next funding time. Its semantics are unverified, so it is not stored or served. |
| Index-price history | No source provides it; only the latest oracle price is kept (per poll). |
| Coinbase and Bitstamp bars | Available, but a second bar source per market would need a merge rule. Kraken alone covers every quoted crypto and live FX market. |
| Metal history (gold-api) | Needs a paid API key. Metals have only accumulated poll values. |
| 1m/5m/15m intervals | Available from the venues but not collected. Storage and collection time scale with them, and no V1.3 consumer needs them. |
